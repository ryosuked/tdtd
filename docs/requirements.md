# 要件定義

ワークスペースの中にカテゴリ、カテゴリの中にタスクを持つ Todo アプリ。Swift のネイティブアプリとして作る。

- 状態の印: ✅ 確定／🟡 仮決め（[OPEN_ITEMS.md](../OPEN_ITEMS.md) で確認待ち）
- データの形の正は [data_model_spec.md](data_model_spec.md)。この文書は「何ができるか」だけを書く

## 1. 用語

| 用語 | 意味 |
|---|---|
| ワークスペース | いちばん外側の入れ物。「仕事」「家」など。インポート・エクスポートの単位 |
| カテゴリ | ワークスペースの中の大分類。タスクは必ずどれか 1 つのカテゴリに属する |
| タスク | やること 1 件 |
| 短冊表示 | カテゴリごとに縦長の列（短冊）を作り、横に並べる表示 |
| 1 欄表示 | ワークスペースの全タスクを 1 本のリストに並べる表示 |

## 2. 対象環境

| 項目 | 内容 | 状態 |
|---|---|---|
| 言語・UI | Swift 6（Strict Concurrency 完全）、SwiftUI | ✅ |
| 対象 OS | 実装開始時点の最新メジャーだけ。`#available` の分岐を書かない | ✅ |
| 端末 | 画面の設計は Mac と iPad の両方が対象。実装と確認は、今は Mac だけ。iPhone は後で足す。基準をどちらにするかは未決 | ✅（基準は 🟡） |
| 対象 OS | macOS 14 以降／iPadOS 26 以降。iOS（後で足す）も 26 以降（[dev_environment_setup](dev_environment_setup.md) §1） | ✅ |
| 通信 | しない。端末間の同期もしない。データの受け渡しはインポート・エクスポート（F5）だけ | ✅ |
| ツール | Apple 公式のツールだけ（Xcode / swift / xcodebuild）。外部の依存は入れない | ✅ |

## 3. 機能要件

### F1. ワークスペース

| ID | 内容 | 状態 |
|---|---|---|
| F1-1 | 作成・名前の変更・削除（確認あり）ができる | ✅ |
| F1-2 | 一覧から切り替えられる。一覧の並び順を手で変えられる | ✅ |
| F1-3 | 次に起動したとき、最後に開いていたワークスペースを開く | ✅ |

### F2. カテゴリ

| ID | 内容 | 状態 |
|---|---|---|
| F2-1 | 作成・名前の変更・色の選択ができる。色は決まったパレットから選ぶ | ✅ |
| F2-2 | 削除できる。中のタスクも一緒に消える。タスクが残っているときは件数を出して確認する | ✅ |
| F2-3 | 並び順を手で変えられる | ✅ |
| F2-4 | カテゴリが 0 個のワークスペースもありうる。そのときは「カテゴリを作る」を案内する | ✅ |

### F3. タスク

| ID | 内容 | 状態 |
|---|---|---|
| F3-1 | 項目は中身（`content`。長い文字列 1 つ、改行可、100,000 文字まで）・期限（日付だけ・任意）・完了。タイトルとメモには分けない。**中身は書式なしの文字列だけ**で、書式付きのドキュメント（太字・リンク・画像など）は扱わない。意図して決めた | ✅ |
| F3-2 | 作成する。新しいタスクはカテゴリの末尾に入る。追加の入力欄は 3 行ほどの高さで、複数行を入れられる | 🟡 |
| F3-3 | 編集・削除・完了／未完了の切り替えができる | ✅ |
| F3-4 | カテゴリの中で並び順を変えられる。別のカテゴリへ移せる | ✅ |
| F3-5 | 完了したタスクはその場に残る。表示するかどうかを切り替えられる（F4-4） | 🟡 |
| F3-6 | 書式付きのテキスト（Web・メモ・Word・Excel など）を貼り付けても、改行が 2 重になったり、見えない文字が残ったりしない。書式は捨て、改行は 1 種類にそろえる（data_model_spec §3.3） | ✅ |

### F4. 表示

| ID | 内容 | 状態 |
|---|---|---|
| F4-1 | 短冊表示: カテゴリの並び順どおりに列を並べる。列の中はタスクの並び順どおり。ドラッグで列の中・列の間を動かせる | ✅ |
| F4-2 | 1 欄表示: カテゴリの並び順にタスクをつなげ、カテゴリ名の見出しで区切る。1 欄表示だけの並び順は持たない | 🟡 |
| F4-3 | 表示モードはワークスペースごとに覚える。エクスポートには含めない | 🟡 |
| F4-4 | 完了したタスクを隠す切り替え。ワークスペースごとに覚える | 🟡 |
| F4-5 | 1 欄表示でタスクを足すときは、カテゴリを選ぶ。最初に選ばれているのは、最後に使ったカテゴリ | 🟡 |
| F4-6 | 短冊表示で、横幅が足りないとき（iPad の Split View、Mac の小さいウィンドウ）は、列を横にスクロールする | 🟡 |
| F4-7 | Mac ではキーボードで操作できる（新規作成・完了の切り替え・削除・表示の切り替え） | 🟡 |
| F4-8 | 一覧（短冊・1 欄）では、タスクの中身を 3 行まで出す。超える分は省く | ✅ |
| F4-9 | 右に詳細のペインを置く。一覧でタスクを選ぶと、中身の全文を出し、編集できる（中身・期限・完了・削除）。ペインは出し入れできる | ✅ |

### F5. インポート・エクスポート

| ID | 内容 | 状態 |
|---|---|---|
| F5-1 | ワークスペースを 1 つ、テキスト（整形した JSON）のファイルに書き出せる（共有シート・ファイルの保存） | ✅ |
| F5-2 | 書き出したファイルを読み込んで、ワークスペースとして追加できる | ✅ |
| F5-3 | 同じ ID のワークスペースがすでにあるときは「置き換える」か「複製として追加する」かを選ぶ | ✅ |
| F5-4 | 形式に合わないファイルは読み込まない。理由を 1 か所に出す。中身を勝手に直さない | ✅ |
| F5-5 | 読み込める上限のサイズを超えるファイルは、開く前に断る（上限は data_model_spec §7） | ✅ |

### F6. 保存

| ID | 内容 | 状態 |
|---|---|---|
| F6-1 | 変更は自動で保存する。保存の操作はない | ✅ |
| F6-2 | 起動時に読めないファイルがあっても上書きしない。別の場所へ退避して知らせる | ✅ |
| F6-3 | 取り消し（Undo）の有無は未決 | 🟡 |

## 4. 非機能要件

| 項目 | 内容 | 根拠 |
|---|---|---|
| 性能 | 1 つのワークスペースにタスクが 5,000 件あっても、操作と保存で引っかからない | 個人で数年分の完了タスクを溜めても収まる量の目安。平均 1 件 約 400 B として 約 2 MB で、ファイルごとの書き直しは数十 ms で終わる。1 件の上限（100,000 文字 ≒ 300 KB）の長文が混じっても、数十件までなら同じ桁に収まる |
| データの安全 | 書き込みは原子的に行う（書きかけのファイルを残さない） | 書き込み中に落ちても、前の版が残るようにするため |
| 応答 | 保存のエンコードと書き込みは MainActor の外で行う | 入力中に画面が止まらないようにするため |
| アクセシビリティ | VoiceOver と Dynamic Type に対応する。タッチのヒット領域は 44pt 以上 | Apple の HIG |
| 言語 | 日本語だけ。文字列は後から翻訳できる形（String Catalog）で持つ | 🟡 |

## 5. v1 の対象外

iPhone、同期（iCloud ほか）、書式付きのテキスト（意図して扱わない。F3-1）、通知・リマインダー、繰り返し、サブタスク、タグ、優先度、検索、共有・共同編集、ウィジェット、時刻付きの期限。

同期は対象外と決めた（v1 だけでなく、今の設計の前提）。サブタスク・時刻付きの期限など、データの形に響くものを足すときは、`schemaVersion` を上げる（data_model_spec §10）。
